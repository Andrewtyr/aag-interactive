# ААГ Интерактив

Это отдельный публичный репозиторий с полной версией ААГ Интерактив. Начните с [карты папок](docs/PROJECT-STRUCTURE.md). Для переноса на сервер со старым сайтом и Apache используйте [инструкцию с восстановлением базы](docs/MIGRATION-APACHE.md).

**Данные не хранятся в GitHub.** Актуальную SQLite-базу, пользователей, ответы и загруженные файлы экспортируют с действующего сервера отдельным закрытым архивом. Инструкция объясняет, как проверить его и развернуть ААГ рядом со старой версией, не перезаписывая её.

Самостоятельный сервис для занятий и мероприятий. Ведущий создаёт материал, проводит его с подключением участников по коду или QR-ссылке и получает отчёт. Цвета интерфейса основаны на оформлении Алтайской академии гостеприимства.

## Что работает сейчас

- Администратор создаёт, удаляет и восстанавливает пользователей, видит активные сессии и журнал действий. У каждого пользователя можно открыть список материалов, отправить материал в архив или восстановить его. Удаление пользователя отзывает вход и участие с аккаунтом.
- Ведущий создаёт материалы в двух вкладках редактора: «Презентация» для собственных слайдов с текстом, фигурами и изображениями и «Интерактив» для тестов, опросов, шкал, открытых вопросов и облака тегов. Интерактивный слайд можно редактировать прямо в его предпросмотре: менять текст, добавлять и перемещать надписи, фигуры, изображения и видео. У слайдов есть макеты, фон, формат 16:9 или 4:3, порядок слоёв, автосохранение и отмена/повтор. Вопросы можно разместить между слайдами и отдельно настроить время, баллы и положение статистики: справа либо по центру под вопросом. Образец «Стандарты гостеприимства» доступен в библиотеке и может быть скопирован.
- В редактор можно загрузить PDF или PPTX. Страницы сохраняют внешний вид; их можно использовать как обычные слайды или выбрать страницу в качестве фона интерактивного вопроса. Шаблон загружается отдельно в настройках вопроса и не добавляет лишние слайды в материал. Текст и объекты исходного файла остаются частью фонового изображения, а вопрос и диаграмма рисуются поверх него.
- Ведущий запускает материал как занятие или мероприятие, задаёт название и категорию, включает рейтинг по желанию и выбирает экран аудитории в окне или на весь экран. Пульт докладчика показывает текущий и следующий слайды, заметки, таймер и ответы. Экран аудитории открывается в отдельной вкладке, а QR-код расположен справа от слайда на широком экране. Если браузер заблокировал вкладку, остаётся ссылка для ручного открытия. Для полного экрана нужно нажать кнопку на экране аудитории. Запущенная сессия хранит копию слайдов, поэтому дальнейшее редактирование исходника не меняет текущий показ.
- Участники подключаются как гости или с аккаунтом по коду, ссылке или QR, отвечают с телефона или компьютера. Сервер контролирует таймер, паузу и один ответ на вопрос; верный ответ может получить бонус за скорость. Ведущий проверяет облако тегов до публикации. Повторяющиеся слова объединяются; частые слова показываются крупнее, самое частое — в центре. Запрещённые слова и выражения задаются по одному на строке в `apps/api/data/word-cloud-blocklist.txt`; файл создаётся автоматически и перечитывается после изменения.
- Административные и авторские данные проверяются сервером для каждой операции. Публичный образец презентации не содержит ключи ответов и заметки ведущего. Баллы за текущий вопрос открываются участнику после закрытия приёма ответов. Успешные подключения ограничены 300 с одного адреса на код за минуту и 5000 на мероприятие; повторное подключение одного аккаунта отклоняется.
- Отдельный экран аудитории показывает слайды и QR; рейтинг публикуется только по команде ведущего. Диаграмма вопроса появляется сразу, ещё до открытия ответов, и обновляется во время голосования. Ведущий может скрыть или снова показать её в пульте, а также поставить по центру и убрать варианты ответов на экране аудитории прямо во время показа. Для теста, опроса и шкалы доступны вертикальные столбцы, горизонтальные полосы и, где применимо, круговая диаграмма. Данные показываются без имён участников и правильного ответа. Открытые ответы можно оценить вручную. Отчёт сохраняет участников и ответы, показывает итоги опросов и баллы для оцениваемых вопросов; его можно выгрузить в CSV.

## Запуск для телефона в одной сети

Подключите компьютер и телефон к одной сети Wi-Fi. В корне проекта выполните `npm start`. Программа покажет адрес сайта для обоих устройств. Если на компьютере есть несколько сетевых подключений и адрес нельзя выбрать автоматически, укажите IP Wi-Fi вручную: `npm start -- --address 10.67.240.158` (замените пример на текущий адрес компьютера). Откройте показанный адрес на компьютере, войдите как ведущий и начните сессию. QR-код и ссылка будут содержать именно этот адрес. На телефоне после сканирования введите имя.

IP компьютера может измениться при смене сети. Если телефон не открывает даже главную страницу, проверьте, что он находится в той же сети, доступ к порту 4180 разрешён брандмауэром Windows и точка Wi-Fi не изолирует устройства друг от друга. Для доступа из интернета нужен домен и серверный запуск с HTTPS, описанный ниже.

## Запуск только на этом компьютере

Нужен Node.js 22 или новее. В корне проекта выполните `npm ci`, затем в `apps/api` — `npm start`. Откройте `http://127.0.0.1:4180/library.html`. Материалы и пользователи сохраняются в `apps/api/data/aag.sqlite`, загруженные презентации — в `apps/api/data/uploads`, список запрещённых слов — в `apps/api/data/word-cloud-blocklist.txt`. Эти пути находятся вне папки публикуемого сайта. На сервере их размещают в закрытом постоянном томе `/data`; управлять материалами пользователей через сайт может только администратор.

На чистой базе создайте первого администратора из каталога `apps/api`: `npm run bootstrap-admin -- admin "Имя администратора"`. Пароль вводится в терминале без отображения. В уже созданной базе повторять эту команду не нужно. Учётная запись администратора также может вести занятия.

Основные адреса: [главная](http://127.0.0.1:4180/), [библиотека](http://127.0.0.1:4180/library.html), [редактор](http://127.0.0.1:4180/editor.html), [пульт ведущего](http://127.0.0.1:4180/host.html), [вход участника](http://127.0.0.1:4180/participant.html), [отчёты](http://127.0.0.1:4180/reports.html), [панель администратора](http://127.0.0.1:4180/admin.html). Ранние демонстрационные экраны сохранены в `preview.html`.

Тесты: из `apps/api` выполните `npm test`. Проверка состояния сервера: `/api/health`. После правки закрытого образца `apps/api/src/hospitality-standards.private.json` обновите публичный предпросмотр командой `node scripts/build-public-preview.mjs` из корня проекта.

[Результаты нагрузочного теста](docs/load-test-2026-09-29.md) и команда `npm run load:test -- 500 10 10` позволяют проверить сценарий 10 × 50 участников на текущем компьютере без изменения рабочей базы.

## Сервер

Подготовлены [пошаговая инструкция и файлы Docker Compose](deploy/README.md) для размещения на собственном сервере с доменом и HTTPS. Команда `npm start` в корне проекта запускает сайт для локальной сети. На постоянном сервере доступный адрес задаётся через `PUBLIC_BASE_URL`.

Перед публичной эксплуатацией на новом сервере проверьте Docker-сборку, восстановление резервной копии, импорт типовых PPTX/PDF и нагрузку на выбранной машине. Импортированные страницы представлены фоном слайда; редактирование отдельных объектов внутри исходного PPTX пока не предусмотрено.
